## 环境准备（开工第一件事）

1. 到 https://godotengine.org/download 下载 **Godot 4.4（标准版，不是 .NET 版）** macOS 版，拖进应用程序文件夹
2. 打开 Godot → Project Manager 界面能正常显示即安装成功
3. 阶段 1 任务 1 会创建工程；之后每次开发就是「AI 编辑器改文件 → 回到 Godot 按 ⌘R(F5) 运行 → 观察 → 反馈」
4. Godot 工程放在仓库的 `game/` 子目录。**Godot 编辑器导入的是 `game/` 这个文件夹**，不是仓库根目录

## 每日工作循环

```
喂任务给 AI 编辑器 → AI 改代码 → Godot 里 F5 运行 → 对照"验证"清单检查
   ↑                                                        │
   └────────── 通过：git commit，下一个任务 ←─────────────────┘
                不通过：把现象描述给 AI 修（最多修 2 轮，仍失败则回退本任务重做）
```

- 每天开工先看 `PROJECT_STATUS.md` 的「下次继续」，收工前更新它
- 每完成一个任务一个 commit，禁止攒一天提交一次

## 风险预案

| 风险 | 预案 |
|---|---|
| 某天进度落后半天以上 | 砍内容不砍质量：5 个探索地点可减为 4 个（砍"张老汉家"，其线索并入义庄），夜晚演出事件可从 4 个减为 2 个 |
| Web 导出出问题（中文字体/音频在浏览器异常） | 阶段 2 结束时（6/15）就做一次 Web 导出冒烟测试，不要等到 6/18 |
| AI 编辑器反复改不好某个 bug | 回退到上一个 commit，把任务拆半重喂；连续两次失败就标记 blocked，换一种实现思路 |
| 素材风格凑不齐 | 全部素材统一做"压暗+降饱和"处理（08 号文档有具体做法），脏旧感恰好是恐怖游戏想要的 |

## 明确不做的事（防止范围膨胀）

种田/经营系统、战斗、背包与道具使用、存档读档（流程仅 15 分钟，不需要）、对话分支选项、多结局、手柄支持、移动端适配。有人（包括 AI 编辑器）提议加这些时，回答是：不做。
